# modules/paper-writing.md · 论文写作主线

> **目标**：把求解结果组织成一份能交、可复算、证据闭环的论文。章节与篇幅按题目自适应；在证据确实充足时，以完整 PDF 50+ 页作为用户内部目标，但绝不把它冒充官方要求或用无效内容凑页。

## 1. 章节结构（推荐顺序，按题目自适应）

1. 摘要页（题目+摘要+关键词，篇幅一般不超过两页）
2. 问题重述与任务拆解
3. 数据审计、模型假设与符号说明（三线表；可按需要拆章）
4. 按问题分别建立、求解、解释并验证模型
5. 跨问题的统一检验 / 灵敏度与鲁棒性（仅在确有共享内容时单列）
6. 模型评价与改进（证据、限制与适用边界）
7. 结论
8. 参考文献
9. 附录（复现说明、代码与补充结果）

> 2026 正式提交 PDF 的首页是官方参赛信息封皮；“匿名”从第二页摘要开始。完整摘要后直接进入正文，正式稿不生成目录。摘要官方表述为“一般不超过两页”，正文页数以当届通知为准。

## 2. 各章写作要点

| 章节 | 写什么 | 常见坑 |
|---|---|---|
| 摘要 | 见 `abstract.md` 专项 | 无数字、无创新点 |
| 问题重述 | 用自己的话重述，不抄题；提炼子问题 | 直接复制题面原文 |
| 问题分析 | 每问先给任务、输入输出、约束、评价标准及与前问依赖；复杂流程再配技术路线图（见 `technical-roadmap.md`） | 写成流水账；无必要也强塞流程图；把前问结果当成未经核验的真值 |
| 模型假设 | 3–5 条，每条"内容+合理性+影响" | 写"不影响结果"空话 |
| 符号说明 | 三线表：符号/含义/单位 | 正文符号与表不一致 |
| 模型建立与求解 | Baseline、主模型、算法/求解器、复杂度或收敛、结果、解释与边界 | 只堆公式不解释；只报最优结果不交代比较口径 |
| 检验/灵敏度 | 见 `validation.md` 六种手段 | 只报训练集 |
| 模型评价 | 用“证据→优势”“限制来源→偏差方向→影响范围→缓解办法”写作 | 假大空夸自己；强行凑优缺点数量 |
| 结论 | 总结每问答案，不引入新结果 | 与摘要重复 |
| 参考文献 | 按引用次序，真实且可核查 | 格式乱、把未使用的 AI 工具虚构为来源 |
| 附录 | 复现环境、输入输出、随机种子、关键参数、运行命令；题面要求时附代码/结果文件说明 | 代码残缺/不可跑；泄露本地绝对路径或身份信息 |

### 2.1 每问的最小充分证据链

每个问题不按固定段数套壳，至少闭合以下七步；不适用项应说明理由后删除：

1. **任务卡**：输入、输出、目标、硬约束、评价指标、与其他问题的依赖关系。
2. **数据与变量**：数据来源、缺失/异常/单位/量纲审计，给出符号、单位和变量域。
3. **Baseline**：朴素规则、经典方法、理论边界或小规模精确解，作为改进的参照。
4. **主模型与求解**：假设、目标/方程/约束、算法流程、关键参数及复杂度或收敛条件。
5. **核心结果**：按“问题答案→量化证据→同口径比较→原因解释→边界/代价”排列。
6. **验证与不确定性**：按数据结构做独立验证，区分观测、参数和情景不确定性，规则见 `validation.md`。
7. **本问结论与传递**：直接回答题目，并列出传给下一问的变量、误差或限制；没有依赖时明确写无。

用户提供的第二十三届社区 LaTeX 参考包已按上述证据链逐项映射。取舍、来源风险与未采用项见 `docs/TEMPLATE_CONTENT_MAPPING_23RD.md`；该参考包只提供内容启发，不得覆盖官方 Word 格式基线。

## 3. 篇幅与页数控制（官方无上限；内部 50+ 为条件目标）

- 截至 2026-09-21，已核对的第二十三届官方格式规范、开赛公告和提交提醒仅明确“摘要一般不超过两页”，没有给出正文最低页数、正文上限或全文总页数上限。
- `page_targets.json` 的**官方页数门禁**保持关闭；其中的 50 页只指“封皮、摘要、正文、参考文献和确有必要的附录组成的完整物理 PDF”内部目标，权限来源是用户偏好，绝不是官方要求。
- 只有同时满足以下条件才追求 50+：每问 §2.1 七步证据链闭合；核心结论均可追溯；基线比较同口径；图、表各有独立信息增量；验证、不确定性和适用边界没有明显缺口；官方版式未被改动。
- 低于 50 页时先做证据缺口审计，只补真实缺项：数据质量与变量/单位说明、关键推导、Baseline 与公平对比、诊断与误差结构、不确定性、灵敏度/鲁棒性、情景分析、复杂度/运行成本、适用边界和复现元数据。若这些内容已经充分，**接受低于 50 页并向用户说明**，不得制造内容。
- 明确禁止：重复背景或结论、教科书式算法抄写、同一数据换图型重复展示、图表与正文逐句复述、无关公式变形、无必要模型叠加、放大图表/字号、强制分页、空白页和无关附录。达到 50 页也不代表质量合格，仍需逐页删冗余。
- 若当届赛题、竞赛系统或后续官方通知明确给出页数限制，立即写入 `contest.json`，并由更新且更具体的官方要求覆盖内部目标。
- 排版目标是“紧凑、清楚、可读”。修复多余分页、浮动体失控和异常大面积空白；允许章节自然结束的正常留白，且不得缩小官方字号、行距或页边距来挤页。

## 4. 边求解边写作

- 不要等到最后一夜写。每问求解完，立刻把"模型+结果+图"填进对应章节。
- 结果一出，先记数字，后润色；数字是骨架。
- 摘要最后写（等所有结果定了），但骨架提前留好。

## 5. 数字一致性纪律

摘要、正文、附录的同一数字必须同源同值。写作时建一张"核心数字表"（哪个问题→哪个指标→哪个值→哪个文件），终稿前逐格核对（见 `polishing.md`）。

## 6. 优秀论文自检表·逐章内嵌（写作时逐条对照）

> 来源：用户提供的第三方"优秀论文自检表"逐条转录（`assets/checklists/优秀论文自检表.md`，机检版 `assets/checklists/paper_checklist.json` + `scripts/paper_checklist.py`）。
> **铁律（执行要求）**：①每完成一个章节，立即对照该表对应章节逐条检查；②总检查时从头到尾全量复查一遍；③最终输出一张**已勾选的自检表**（做到打 ✅），必须 100% 闭环；④任何做不到的条目不得静默跳过——必须显式标注"不适用/未做到+原因"，由用户确认后记录在案。
> 下列条目 ID 与转录稿一一对应。原转录 3 处存疑（M14、V05、I02）**已经用户确认定稿**，无待确认项。

### 6.1 全局格式（F01–F06，硬性）

- **F01** 论文题目用**三号黑体字**。
- **F02** 一级标题用**四号黑体字，居中**。
- **F03** 二级、三级标题采用**小四号宋体字**；左对齐是官方 Word 模板的默认实现，不应误写成“官方正文黑体要求”。
  > 已按 2026 官方文件核对：官方原文只明确题目三号黑体、一级标题四号黑体居中，以及“其他汉字一律小四宋体、单倍行距”。因此二、三级标题的宋体是硬格式，左对齐是模板默认。
- **F04** 论文中其他汉字一律用**小四号宋体字**；排版文本中的英文、阿拉伯数字和西文标点使用 **Times New Roman**。Overleaf 缺少微软字体时仅允许 `TeX Gyre Termes` 兼容回退；公式使用 Times-compatible 数学字体，代码保留等宽字体。
- **F05** 行距用**单倍行距**。
- **F06** 打印文字内容尽量避免彩色打印（必要的彩色图形、图表除外）。

**模板命令核对结果（以已修正的 `gmcmthesis.cls` 和 docs/OFFICIAL_FORMAT_2026.md 为准）**：

| 条目 | 要求 | gmcmthesis.cls 实际命令 | 是否满足 |
|---|---|---|---|
| F01 | 三号黑体题目 | 默认 `\maketitle` 以 `\zihao{3}\heiti` 输出题目 | ✅ |
| F02 | 四号黑体居中一级标题 | `\section` 使用 `\zihao{4}\heiti` 与居中格式 | ✅ |
| F03 | 小四宋体二三级标题 | `\subsection`/`\subsubsection` 使用宋体小四；左对齐为模板默认 | ✅ |
| F04 | 小四宋体正文；西文 Times 系 | `ctexart` 小四基线与宋体正文；本地 Times New Roman、Overleaf TeX Gyre Termes 回退；公式 TeX Gyre Termes Math | ✅ |
| F05 | 单倍行距 | `\setstretch{1}` | ✅ |
| F06 | 避免彩色打印 | `bwprint` 选项与出图检查 | 由选项/出图控制 |

官方 Word 模板的视觉与样式核对结果：题目黑体 16 pt 居中、一级标题黑体 14 pt 居中、正文宋体 12 pt 单倍、二/三级标题宋体 12 pt 左对齐；样式 XML 的 ASCII/HAnsi 字体为 Times New Roman。前置标签为隶书 18 pt；具体页边距、字体回退与页码规则见 docs/OFFICIAL_FORMAT_2026.md。

### 6.2 自检表单一来源与适用性

138 个检查 ID 的唯一文本来源是 `assets/checklists/优秀论文自检表.md`，结构化元数据位于 `assets/checklists/paper_checklist.json`；本模块不再复制整表。F01–F06 是官方格式硬约束，其余条目按题面、数据结构和证据状态判断“通过/不适用/未做到”，不得为全绿强塞章节、算法、图表或固定页数。

写作时以 §2.1 的七步证据链为主轴；条目只负责查漏，不反向支配论文逻辑。完成一章即运行或人工核对对应 ID，终稿再全量闭环。

### 6.3 已纠正的高风险旧规则

- 摘要一般不超过两页；不要求刚好一页。可保留支撑核心结论的一项验证证据和必要因果/边界。
- 摘要的主要模型、决定性数值及核心结论/创新点选择性加粗；普通数字不机械加粗，禁止整句或整段加粗。
- 假设数量不与问题数量绑定；熵权法、XGBoost、五折交叉验证都不是默认答案。
- 验证划分服从 IID、分组、时间或空间结构；评价类同样需要权重/排序稳定性检验。
- 图表宽度、段数、分点和加粗按可读性决定；模型优势数量不必大于局限。
- DOI 不是官方强制删除项；参考文献以当届官方字段与引用顺序为准。

### 6.4 "写完即勾"总则

- 每写完一章，立刻打开 `assets/checklists/优秀论文自检表.md`，按上述 ID 逐条勾选。
- 写作阶段不必等全稿：边写边勾，最后总查时再全量复查一遍（见 `polishing.md` 终审闭环）。
- 勾不上的条目，不静默跳过：标注"不适用/未做到+原因"，交用户确认后写入 sidecar（`paper_checklist_decisions.json`）。

## 7. 边界

- 不代写整篇成品论文；本模块给结构与要点，内容从你自己的求解来。
- 当前没有官方正文页数目标；完整 PDF 50+ 仅为证据条件式内部目标，任何时候都不注水。
- 章节名/顺序以当届官方模板（`assets/paper-template/`）为准。
