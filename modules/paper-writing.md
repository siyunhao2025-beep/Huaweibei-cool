# modules/paper-writing.md · 论文写作主线

> **目标**：把求解结果组织成一份能交、可复算、证据闭环的论文。章节按题目自适应；Figure 总数锁定后，由用户决定完整 PDF 的最终长度，任何页数选择都不得成为注水理由。

## 1. 章节结构（推荐顺序，按题目自适应）

1. 摘要页（匿名题目+完整摘要+关键词固定在一个逻辑页，正文从下一页开始）
2. 问题重述与任务拆解
3. 数据审计、模型假设与主要符号说明（符号表为必备三线表；默认置于第一问推导和首个模型公式前）
4. 按问题分别建立、求解、解释并验证模型
5. 跨问题的统一检验 / 灵敏度与鲁棒性（仅在确有共享内容时单列）
6. 模型评价与改进（证据、限制与适用边界）
7. 结论
8. 参考文献
9. 附录（复现说明、代码与补充结果）

> 2026 正式提交 PDF 的首页是官方参赛信息封皮；“匿名”从第二页摘要开始。完整摘要后直接进入正文，正式稿不生成目录。官方原文是摘要“一般不超过两页”；本 skill 按用户最新裁决采用更严格的单页摘要页内部规则，不把它冒充官方要求。正文页数以当届通知为准。
>
> 参考文献另起一页；存在附录时，附录另起一页。LaTeX 在两个边界使用 `\clearpage`，Word 对相应一级标题启用“段前分页”。这是结构边界，不是为了凑页添加空白。
>
> 可复制的前置写作骨架见 `assets/paper-template/章节模板/任务映射与总体分析模板.tex`：它把“题面口径—任务映射—成功条件—总体证据链—复杂度/验证安排”落实成可编辑 LaTeX，但不是固定目录。简单题或不存在共享接口时删除总体分析及共享数据小节；不得固定问题数量、题型或算法顺序。

## 2. 各章写作要点

| 章节 | 写什么 | 常见坑 |
|---|---|---|
| 摘要 | 见 `abstract.md` 专项；题目优先单行，完整摘要和 3--6 个关键词与题目同页 | 无数字/代价/边界；题目三行或极短尾行；摘要跨页；用缩字挤版或空话填页 |
| 问题重述 | 用自己的话重述，不抄题；提炼子问题 | 直接复制题面原文 |
| 问题分析 | 每问标题后先用短导读回溯任务与前问输入，概括方法路线和本问交付；再展开输入输出、约束、评价标准；复杂流程才配技术路线图（见 `technical-roadmap.md`） | 标题后直接进公式；照抄题面；用“本节将分析并得到结果”空转；把前问结果当成未经核验的真值 |
| 模型假设 | 3–5 条，每条"内容+合理性+影响" | 写"不影响结果"空话 |
| 主要符号说明 | 置于基本假设/总体问题分析后、第一问推导与首个模型公式前；三线表给出全局核心符号、含义及适用的单位/取值域，并由正文引用 | 把局部参数全塞入总表；缺 `caption/label/ref`；有竖线/网格线；靠缩放或小字挤表；正文符号与表不一致 |
| 模型建立与求解 | Baseline、主模型、算法/求解器、复杂度或收敛、结果、解释与边界 | 只堆公式不解释；只报最优结果不交代比较口径 |
| 检验/灵敏度 | 见 `validation.md` 六种手段 | 只报训练集 |
| 模型评价 | 用“证据→优势”“限制来源→偏差方向→影响范围→缓解办法”写作 | 假大空夸自己；强行凑优缺点数量 |
| 结论 | 总结每问答案，不引入新结果 | 与摘要重复 |
| 参考文献 | 另起一页；按引用次序，真实且可核查 | 与正文挤在同页；格式乱；把未使用的 AI 工具虚构为来源 |
| 附录 | 另起一页；写复现环境、输入输出、随机种子、关键参数、运行命令；计算型论文加入与真实脚本/产物逐步对应的代码式伪代码 | 与参考文献挤在同页；用空函数冒充算法；粘贴大段无关源码；泄露本地绝对路径或身份信息 |

### 2.A 全文启动：先锁任务映射，再选模型

多问题赛题开始写正文前，先完成一张任务映射表：每问只登记题面输入与硬约束、数学任务、输出与成功条件、真实的上下游依赖。这里的“数学任务”描述需要计算、解释或决策的对象；方法尚未比较时不得提前填入算法名。成功条件必须在建模前冻结指标、单位、方向、阈值或可行性口径，不能看到结果后再换标准。

任务表不是为了把所有问题强串成一条流水线。只有确实传递数据、参数、中间结果或约束时才登记依赖，并说明误差如何传播；相互独立时明确写“无”。若多个问题共享数据、变量口径、训练/验证/测试边界或模型递进关系，再保留“总体建模框架与证据链”；否则直接进入模型假设、主要符号说明和各问题章节，避免重复叙述。

可复制骨架见 `assets/paper-template/章节模板/任务映射与总体分析模板.tex`。该文件吸收用户提供的第二十三届社区参考包的有效写作结构，但已去掉目录页、固定问题数量、固定“结构识别—预测—优化”映射、通用公式和示例结论。任何标题不适用就删除，不得为“八股完整”保留空壳。

### 2.0 每问开篇的“回溯—路线—交付”导读

每个“问题一/第 1 问”等一级问题标题后，先写一段让读者进入本问的导航，再出现首个小标题、公式、图表或算法。该段不是重复“问题重述”，而是把全局任务切换到当前问题：

1. **回溯题意与接口**：用自己的话说明本问在求什么，使用哪些已知输入；只写真实存在的前问依赖，没有依赖就明确为独立分支。
2. **概括求解路线**：说明为什么选择该思路，并用“先—再—最后”或等价逻辑交代方法链；只点出关键机制，不在导读里展开公式和参数。
3. **定位结果交付**：说明本问最终会给出哪类预测、方案、比较、区间或决策，以及它怎样回答题目或传给下一问。证据已经锁定时可以预告结论方向，尚未锁定时只写交付类型，不抢写数字。

通常用 2--4 句连续正文即可，长度随问题复杂度调整。禁止使用“本节将对问题进行分析，建立模型并得到结果”这类可替换到任何题目的空话；合格导读必须出现本题对象、实际方法链和明确交付。导读之后再按“定义口径 → 建模/求解 → 结果解释 → 验证 → 本问结论/传递”展开，避免先报结果、后补方法或尚未定义概念提前出场。

### 2.1 主要符号说明三线表合同

每份正式论文都必须有且仅有一张“主要符号说明”总表。这是用户确认的内部生产规则，已核对的 2026 官方文件没有把符号表单列为硬性条款，因此不得把它写成“官方要求”。默认顺序是“总体问题分析/数据审计 → 基本假设 → 主要符号说明 → 问题一”；无独立假设章时，也必须放在第一问的模型推导和全文首个模型公式之前，让读者先取得统一符号口径。表格整体按版心和列宽自然排布，不额外硬编码“必须居中”的审计条件。

表内只收录跨小问复用、出现在核心模型或评价口径中、或不定义就会妨碍阅读全文的符号。仅在一处公式使用的系数、循环索引和局部中间量，在首次出现的公式前后就近定义；禁止为了“看起来完整”把所有参数堆进总表。符号、上下标、粗斜体、集合、单位和正文首次定义必须逐项一致，同一概念不得在表内外换名。

LaTeX 最小合同如下：

1. 表前正文明确写“全文主要符号见表~`\ref{...}`”，不得只摆表不引用。
2. 使用 `table` + `tabularx`；确实需要跨页时才使用 `longtable`。表必须具有语义明确的 `\caption` 和唯一 `\label`。
3. 同一张表内依次出现 `\toprule`、`\midrule`、`\bottomrule`；列格式中不得含竖线，正文不得用 `\hline`、`\cline` 或网格线伪装三线表。
4. 表头至少含“符号”和“含义/定义”；量纲适用时增加“单位”，无量纲、集合或范围更重要时写“单位/取值域”，并使用 `--` 明确无量纲/不适用，不能留空造成歧义。
5. 保持官方正文字号。禁止用 `\resizebox`、`\scalebox`、`\small`、`\footnotesize`、`\scriptsize`、`\tiny` 等压缩整表；内容过长时先缩短释义、合理换行或拆除局部符号。Word 派生稿须保留三线边框、题注、表前引用语义与可追溯标签文本；它不是 LaTeX `\ref` 的等价实现，若正式交付 Word，必须在 Word 中另行更新并复核实际表号与交叉引用。`audit_docx.py` 可独立核对章节顺序、引用语义、题注和三线边框，但 Word 派生时公式已转为普通文本，“主符号表位于全文首个模型公式之前”仍以权威 TeX 源的 `audit_tex.py` 检查为准。

可复制骨架见 `assets/paper-template/章节模板/符号说明模板.tex`。模板中的“待替换”占位行必须换成本题真实符号后才能通过审计并入稿。

### 2.2 每问的最小充分证据链

每个问题不按固定段数套壳，至少闭合以下七步；不适用项应说明理由后删除：

1. **任务卡**：输入、输出、目标、硬约束、评价指标、与其他问题的依赖关系。
2. **数据与变量**：数据来源、缺失/异常/单位/量纲审计，给出符号、单位和变量域。
3. **Baseline**：朴素规则、经典方法、理论边界或小规模精确解，作为改进的参照。
4. **主模型与求解**：假设、目标/方程/约束、算法流程、关键参数及复杂度或收敛条件。
5. **核心结果**：按“问题答案→量化证据→同口径比较→原因解释→边界/代价”排列。
6. **验证与不确定性**：按数据结构做独立验证，区分观测、参数和情景不确定性，规则见 `validation.md`。
7. **本问结论与传递**：直接回答题目，并列出传给下一问的变量、误差或限制；没有依赖时明确写无。

用户提供的第二十三届社区 LaTeX 参考包已按上述证据链逐项映射。取舍、来源风险与未采用项见 `docs/TEMPLATE_CONTENT_MAPPING_23RD.md`；该参考包只提供内容启发，不得覆盖官方 Word 格式基线。

### 2.3 二、三级标题下的内容合同

标题不是目录标签，而是对读者作出的“本节会回答什么”承诺。普通 `\subsection` / `\subsubsection` 不重复 §2.0 的四项导读，也不要求每节机械覆盖问题、证据、方法、结果和接口；但标题下必须有与标题直接相关的实质正文，不能只有公式、图表或一句空泛过渡。

写作阶段若需要防止漏项，可以先用下面的 LaTeX 注释卡做草稿；它是可选的写作脚手架，不是提交内容，也不能替代正文或充当自动审计凭证：

```tex
% 本节问题：这一小节具体回答哪一个判断或计算问题？
% 输入/证据：使用哪些题面条件、数据、脚本输出、图表或文献？
% 方法/定义：需要定义哪些变量、模型、公式、算法或比较口径？
% 结果：本节必须交付哪个数字、规律、方案或负结果？
% 解释/边界：为什么出现该结果，在哪些条件下成立，代价是什么？
% 接口：本节输出是否进入下一小节/下一问；若没有，写“无”。
```

正文不得出现“标题后只有公式/图表”“标题下只有一句空泛过渡”“连续两个标题之间无实质内容”。某个局部标题只承担定义、数据审计或限制条件时，就把该职责讲清，不虚构结果或下游接口；题型不需要某项时删掉该标题，而不是保留空壳。各常用标题的具体内容见 `docs/TEMPLATE_CONTENT_MAPPING_23RD.md` §4；可选注释卡已写入 `assets/paper-template/章节模板/`。

### 2.4 图文叙述合同

每张 Figure 按“图前定位—图注解码—证据读数—原因/机制—论文含义—边界/转折”闭环，细则见 `figures-interface.md` §4.1。图后不能只报结果：必须解释为什么出现该现象、它怎样支持或限制本问答案，以及下一步如何使用；因果证据不足时只写相关性和待验证机理。复合图逐个解释关键面板并综合，流程图解释模块、箭头、依赖和数据隔离。总流程图还须通过 `technical-roadmap.md` 的六联入稿门禁。论文初稿阶段就写完整图解，不把“以后再补说明”留到终审。

大图的顺序还要形成可连续阅读的证据链。同一小节可有多张顶层 Figure，但不能让两张大图在源码和成品页中背靠背出现；上一图闭环解释完成后，至少写一段、复杂关系写两段自然过渡，再引出下一图。过渡应同时说清：上一图已经回答了什么或暴露了什么限制，为什么仅凭它还不够，下一图具体补哪一项比较、验证、机制或边界。标题、空行、`\clearpage`、公式/表格以及“下面给出下一图”均不能代替这段论证；复合图的子面板仍按一张顶层 Figure 处理。机器门禁只守住至少一段实质承接的下限，终审还需人工判断语义是否真实、是否应把重复大图合并。编译后还要逐页看最终 PDF；若浮动机制仍把两张大图排在一起，只在问题位置使用 `[H]` 或语义边界处的 `\FloatBarrier` 恢复顺序，不把全局强制定位当默认模板，以免制造大片空白。

### 2.5 附录代码式伪代码合同

凡正文结论依赖数据处理、数值求解、仿真、优化或模型训练，附录必须至少给出一段代码式伪代码。它不是用几行 `import` 和空函数装饰版面，也不是把完整仓库复制进论文；目标是让读者看清真实计算顺序、数据权限和产物落点。

伪代码至少覆盖：

1. **输入与审计**：实际输入类型、只读/哈希/CRC/形状/单位等本题真正执行的检查。
2. **可复现配置**：实际随机种子、固定阈值、求解器或冻结配置；没有随机性时明确写确定性规则。
3. **数据或求解边界**：训练—验证—测试、时间/事件/空间隔离，或优化/仿真的等价独立验证边界；不适用的环节不得硬造。
4. **核心算法链**：按问题顺序保留真实运行过的函数级步骤，并与正文模型名称一致。
5. **独立检验与导出**：测试只开一次、Bootstrap/灵敏度/可行性检查等实际执行项，以及真实结果文件或图表索引。

每一段前后用短表或一句话给出“伪代码步骤 → 实际脚本/函数 → 结果文件”的映射。允许使用 `Python`、`Matlab`、`lstlisting`、`algorithm`/`algorithmic` 等代码式环境；Word 派生稿须保留逐行结构、缩进、换行和语法着色。按用户内部字体裁决，代码中的西文也使用 Times New Roman（Overleaf 回退 TeX Gyre Termes），不以 Courier 等等宽字体替代；这不是官方新增要求。禁止 `TODO`、`pass`、省略号、`audit_and_clean()`、`build_features()`、`solve_model()` 等没有真实实现映射的占位符，禁止写入未运行的深度模型、虚构箭头/收益、身份字段和本机绝对路径。完整可运行源码放复现包，论文附录只保留最小充分框架。

manifest 顶层必须显式写入 `appendix_pseudocode`：计算型论文用 `{"required": true}`，并声明实际附录章节；确无程序求解时用 `{"required": false, "reason": "具体、可核验的不适用理由"}`。缺失裁决、含糊理由或 `required=true` 却没有附录均直接失败。`required=false` 只允许纯解析题免于新增伪代码，不能让已经写入附录的代码块、伪代码标题或代码框架绕过完整性与可追溯性审计。`scripts/audit_tex.py` 检查代码环境、输入—计算—验证—输出语义、脚本/产物映射和占位符。

## 3. 篇幅确认卡（Figure 锁定后由用户决定）

- 截至 2026-09-22，已核对的第二十三届官方格式规范、开赛公告、提交提醒及赛事首页最新通知仅明确“摘要一般不超过两页”，没有给出正文最低页数、正文上限或全文总页数上限。本 skill 另按用户裁决把题目+摘要+关键词锁在一个逻辑页；该内部规则不改变官方事实。
- `page_targets.json` 的**官方页数门禁**保持关闭。初始 `internal_total_page_target.mode=user_decides`，表示尚未得到用户裁决，不代表任何默认页数。
- Figure 总数锁定后，根据已登记的模型、推导、实验、Figure/Table、验证与必要附录给出**证据支撑的预计区间**，不得用“每张图固定增加 X 页”之类伪精确换算。然后只请用户二选一：

```text
论文篇幅确认卡
已锁定 Figure：N 张
按现有证据预计完整物理 PDF：L–U 页（含第 0 页封皮、摘要、正文、参考文献及必要附录）
主要篇幅来源：……
若选择区间外页数，仍缺/需删的证据：……

请回复：论文总页数：XX
或：论文长度：证据充分即可
```

- 用户给具体页数时，将 mode 改为 `user_locked`、target 写为 XX，并记录确认；用户选择“证据充分即可”时，将 mode 改为 `off`、authority 写为 `user_decision_no_fixed_target`。两者都不是官方要求。
- 用户后来增加 Figure 时，新增图必须带来相应的方法/实验、结果解释、验证或边界内容；重新估算区间并再次让用户决定篇幅。Figure 变多只会在有真实信息增量时增长论文，不自动按张数堆字。
- 若用户目标超出可支撑范围，明确列出缺失的数据、实验或推导，请用户在“补证据 / 调整目标”之间裁决；不得先写空话占页。若目标偏短，优先合并重复证据与压缩叙述，不得删掉回答题目所必需的结论。
- 明确禁止：重复背景或结论、教科书式算法抄写、同一数据换图型重复展示、图表与正文逐句复述、无关公式变形、无必要模型叠加、放大图表/字号、除摘要后/参考文献前/附录前之外的凑页式强制分页、空白页和无关附录。达到用户页数也不代表质量合格，仍需逐页删冗余。
- 若当届赛题、竞赛系统或后续官方通知明确给出页数限制，立即写入 `contest.json`，并由更新且更具体的官方要求覆盖内部目标。
- 排版目标是“紧凑、清楚、可读”。修复多余分页、浮动体失控和异常大面积空白；允许章节自然结束的正常留白，且不得缩小官方字号、行距或页边距来挤页。

## 4. 边求解边写作

- 不要等到最后一夜写。每问求解完，立刻把"模型+结果+图"填进对应章节。
- 写每问正文前先完成 §2.0 的导读；结果变化时只更新交付或结论方向，不把详细指标重复搬到开篇。
- 结果一出，先记数字，再同步记录“出现原因/机制证据、对本问的含义、不能外推的边界”，最后润色；数字只是骨架，不是完整论证。
- 摘要最后写（等所有结果定了），但骨架提前留好。

## 5. 数字一致性纪律

摘要、正文、附录的同一数字必须同源同值。写作时建一张"核心数字表"（哪个问题→哪个指标→哪个值→哪个文件），终稿前逐格核对（见 `polishing.md`）。

## 6. 优秀论文自检表·逐章内嵌（写作时逐条对照）

> 来源：用户提供的第三方"优秀论文自检表"逐条转录（`assets/checklists/优秀论文自检表.md`，机检版 `assets/checklists/paper_checklist.json` + `scripts/paper_checklist.py`）。
> **铁律（执行要求）**：①每完成一个章节，立即对照该表对应章节逐条检查；②总检查时从头到尾全量复查一遍；③最终输出一张**已勾选的自检表**（做到打 ✅），必须 100% 闭环；④任何做不到的条目不得静默跳过——必须显式标注"不适用/未做到+原因"，由用户确认后记录在案。
> 下列条目 ID 与转录稿一一对应。原转录 3 处存疑（M14、V05、I02）**已经用户确认定稿**，无待确认项。

### 6.1 全局格式（F01–F06，硬性）

- **F01** 论文题目用**三号黑体字**。
- **F02** 一级标题用**四号黑体字，居中**。
- **F03** 二级、三级标题采用**小四号宋体字**；左对齐是官方 Word 模板的默认实现，不应误写成“官方正文黑体要求”。
  > 已按 2026 官方文件核对：官方原文只明确题目三号黑体、一级标题四号黑体居中，以及“其他汉字一律小四宋体、单倍行距”。因此二、三级标题的宋体是硬格式，左对齐是模板默认。
- **F04** 论文中其他汉字一律用**小四号宋体字**；排版文本（含代码环境）中的英文、阿拉伯数字和西文标点使用 **Times New Roman**。Overleaf 缺少微软字体时仅允许 `TeX Gyre Termes` 兼容回退；公式使用 Times-compatible 数学字体。代码仍保留逐行结构、缩进和换行，但不再以等宽字体作为字体例外；这是用户内部裁决，不冒充官方条款。
- **F05** 行距用**单倍行距**。
- **F06** 打印文字内容尽量避免彩色打印（必要的彩色图形、图表除外）。

**模板命令核对结果（以已修正的 `gmcmthesis.cls` 和 docs/OFFICIAL_FORMAT_2026.md 为准）**：

| 条目 | 要求 | gmcmthesis.cls 实际命令 | 是否满足 |
|---|---|---|---|
| F01 | 三号黑体题目 | 默认 `\maketitle` 以 `\zihao{3}\heiti` 输出题目 | ✅ |
| F02 | 四号黑体居中一级标题 | `\section` 使用 `\zihao{4}\heiti` 与居中格式 | ✅ |
| F03 | 小四宋体二三级标题 | `\subsection`/`\subsubsection` 使用宋体小四；左对齐为模板默认 | ✅ |
| F04 | 小四宋体正文；西文 Times 系 | `ctexart` 小四基线与宋体正文；本地 Times New Roman、Overleaf TeX Gyre Termes 回退；公式 TeX Gyre Termes Math | ✅ |

### 6.2 自检表单一来源与适用性

138 个检查 ID 的唯一文本来源是 `assets/checklists/优秀论文自检表.md`，结构化元数据位于 `assets/checklists/paper_checklist.json`；本模块不再复制整表。F01–F06 是官方格式硬约束，其余条目按题面、数据结构和证据状态判断“通过/不适用/未做到”，不得为全绿强塞章节、算法、图表或固定页数。

写作时以 §2.2 的七步证据链为主轴；条目只负责查漏，不反向支配论文逻辑。完成一章即运行或人工核对对应 ID，终稿再全量闭环。

### 6.3 已纠正的高风险旧规则

- 官方只写摘要一般不超过两页；本 skill 后续按用户裁决把题目、完整摘要和关键词固定在一个逻辑页。单页是跨度上限，不是必须填满版心的最低字数；可保留支撑核心结论的验证证据、代价和必要边界。
- 摘要的主要模型、决定性数值及核心结论/创新点选择性加粗；普通数字不机械加粗，禁止整句或整段加粗。
- 假设数量不与问题数量绑定；熵权法、XGBoost、五折交叉验证都不是默认答案。
- 验证划分服从 IID、分组、时间或空间结构；评价类同样需要权重/排序稳定性检验。
- 图表宽度、段数、分点和加粗按可读性决定；模型优势数量不必大于局限。
- DOI 不是官方强制删除项；参考文献以当届官方字段与引用顺序为准。

### 6.4 "写完即勾"总则

- 每写完一章，立刻打开 `assets/checklists/优秀论文自检表.md`，按上述 ID 逐条勾选。
- 写作阶段不必等全稿：边写边勾，最后总查时再全量复查一遍（见 `polishing.md` 终审闭环）。
- 勾不上的条目，不静默跳过：标注"不适用/未做到+原因"，交用户确认后写入 sidecar（`paper_checklist_decisions.json`）。

## 7. 边界

- 不代写整篇成品论文；本模块给结构与要点，内容从你自己的求解来。
- 当前没有官方正文页数目标；完整 PDF 长度由用户在 Figure 锁定后裁决，任何时候都不注水。
- 章节名/顺序以当届官方模板（`assets/paper-template/`）为准。
