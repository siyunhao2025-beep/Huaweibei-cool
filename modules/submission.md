# 提交规范

本模块以 docs/OFFICIAL_FORMAT_2026.md 记录的第二十三届开赛公告、上传手册和三份官方 Word 文件为准。当届题面、竞赛系统或后续通知有更新时，以更新文件覆盖。

## 1. 版式与匿名

- [ ] A4；上 3.00 cm、下 1.75 cm、左/右各 2.25 cm。
- [ ] 物理第 1 页为官方参赛信息封皮，四个 logo 未替换；物理第 2 页完整含匿名题目、摘要和 3--6 个关键词；物理第 3 页直接开始正文，未插入目录。
- [ ] 封皮中的学校、参赛队号和三名队员姓名均已填写真实值；不是空白模板、`TODO` 或“待替换”占位文本。
- [ ] 页码从摘要页起，页脚中部阿拉伯数字从 1 连续编号；无页眉。
- [ ] 学校、成员姓名和队伍编号只出现在封皮；摘要、正文、参考文献和附件内容无身份标志、邮箱、Git 用户名或本地路径。
- [ ] 题目三号黑体；一级标题四号黑体居中；其他汉字小四宋体；单倍行距。
- [ ] 摘要内容包含建模思路、方法、模型、决定性结果与结论、创新点/边界和关键词；按用户内部规则与题目共同占一个逻辑页，无需英文翻译。官方原文仍是“一般不超过两页”。
- [ ] 正文引用使用 [n]；书籍、期刊、网络资源和程序来源均按官方字段完整列出。

2026 开赛公告明确要求首页封皮不可删除。正式提交使用带 `\makeidentitycover` 的模板；“匿名”仅指封皮之后的摘要和正文。纯匿名稿可用于内部审阅，但不能上传到正式论文入口。

## 2. AI 使用规定：按实际使用方式检查

先如实确认是否使用 AI；不得为了通过检查而虚构“未使用”或虚构披露。

- [ ] 未使用 AI：无需伪造 AI 披露，继续完成其余提交检查。
- [ ] 使用 AI 辅助写作：队伍已理解输出，最终文字由队伍用自己的语言表达。
- [ ] 使用 AI 生成模型/公式：已有正式来源或可核查推导；若以 AI 输出作来源，已按规定标注工具、版本/型号、开发者/公司和发布日期，并认识到可能不被认可的风险。
- [ ] 使用 AI 辅助数据分析：结果前后已标注工具、版本、开发者和发布日期。
- [ ] 使用 AI 辅助编程：程序开头已有规定的 AI 辅助及工具信息注释。
- [ ] 题目另有要求时：已另附 AI 输入内容与后续处理策略，包括技术路线、假设、参数/超参数等。

无推导、无引用、无可确认来源的模型或公式不写入论文。违反 AI 使用规定可能取消评奖资格。

## 3. MD5、上传与附件

- [ ] 最终 PDF 按“题号字母+队伍编号”命名，例如 `A26000010001.pdf`，不压缩。
- [ ] 先用最终 PDF 生成并提交 MD5；提交 MD5 后不再修改、重导出或替换 PDF。
- [ ] 上传与 MD5 完全一致的 PDF，并在上传成功后点击系统“提交”按钮。
- [ ] 附件仅在题目明确要求或确有助于评审且论文已注明时上传；使用 `题号+队伍编号.rar`，不超过 50 MB。
- [ ] 所有图表和摘要数字均可追溯到实际求解结果。
- [ ] 用真实最终 PDF、与 paper checklist 一致的 TeX 主稿、该主稿的原始 manifest、`提交附件/`、实际 AI 使用方式和 AI 说明文件运行 `submission_audit.py --paper 提交附件/最终论文.pdf --source 论文/main.tex --manifest 论文/论文输入.json --attachments 提交附件 --ai-used mixed --ai-file 提交附件/AI使用说明.txt --cover-policy required --report 论文/submission_audit.json --json`，并处理所有失败项；`--ai-used` 与 `--ai-file` 按真实情况填写，不能照抄示例。正式报告不得以“未发现 manifest”跳过：P6 会绑定并现场复核 manifest 路径/SHA-256，复用 `audit_paper.py` 强制检查单页摘要（题目/摘要/关键词/字号/正文第 3 页）以及参考文献/附录物理页首，再用现场编译、页面几何及固定 DPI 像素哈希防止“源稿 A+无关 PDF B”或视觉篡改。纯无附录稿合法，但 manifest 仍须恰有一个 `references` 角色。TeX 正式源同时运行 `audit_tex.py --require-filled-cover`，脚本的 warning 仍需人工裁决。
- [ ] 运行 `python scripts/paper_checklist.py --tex 论文/main.tex --problems <题数> --archetype <题型> --outdir 论文 --strict`，将人工条目明确记录为通过或不适用；随后运行 `python scripts/progress.py --root . --gate P6`，由门禁现场重算机器项、逐项核对 sidecar，并用报告参数重跑提交审计。`--tex`、题数和题型必须换成当前项目真实值，不能裸跑 `--strict`。
- [ ] 上传后保留竞赛系统回执。
- [ ] 完成四段闭环：全量求解链重跑、源码/自动审计、最终 PDF 逐页视觉检查、从实际上传包解压重编译并复审。

留出至少一小时用于最终 PDF 打开、页码、匿名、附件和系统回执的人工复核。

## 4. 终稿全量重跑与覆盖旧件

当用户说“重新跑一遍”“给最终完整 PDF”或“覆盖错误的”时，按下面顺序执行；旧 PDF 编译成功不代表结果链已经更新。

1. **冻结权威入口**：记录题面与原始数据校验值、主求解脚本、依赖顺序、随机种子/冻结配置、权威 TeX、图表真实读取目录、全部交付副本与压缩包。找不到唯一权威入口时先停下排歧义。
2. **可恢复地隔离旧产物**：先备份现有交付件；把模型派生缓存、案例快照和自动复用的中间结果移到带时间戳的备份目录，不删除原始数据，不让“文件已存在”跳过重算。
3. **按依赖图全量重跑**：从数据审计、基线/主模型、验证与不确定性，到图表和论文表格依次执行并留运行日志。与冻结结果逐项对比；差异只能来自已记录的源码、环境或输入变化，原因不明即停止交付。
4. **同步真实排版输入**：重新生成的 Figure/Table 要复制到权威 TeX 实际读取的目录，再核对调用路径、Figure 锁定数、表格数量和内容哈希；不能只更新旁路导出目录。
5. **双重构建与同源比较**：权威目录 XeLaTeX 双遍编译；随后把声明的源码、图、表和依赖复制到隔离目录干净构建。比较页数、每页尺寸、规范化文本哈希和固定 DPI 页面渲染哈希。原始 PDF 字节哈希用于标识交付物，但因元数据/时间戳可变，不单独证明内容等价。
6. **逐页看成品**：渲染全部页面，逐页检查摘要页、符号表、每组大图与过渡、长表、参考文献、附录和末页；自动审计通过不能替代肉眼确认裁切、重叠、乱码、浮动体重排和可读性。
7. **原子更新交付集合**：所有门禁通过后，才把同一个已审计 PDF 一次性写入全部交付别名；重建 Overleaf/源码包与复现包，解压源码包再次编译，更新页数、文件大小、审计结论和 SHA-256 清单。任一包仍能重编出旧稿，交付就未闭环。
8. **分清审阅版与正式提交版**：历史题复现、空白学校/队号/队员字段或当届规则未核定时，可以交付“内部审阅 PDF”，但不得写成“正式参赛可提交”。生成 MD5 后禁止再改 PDF。

本节中的全量重跑、缓存失效、压缩包重建和交付别名同步目前包含人工流程证据；`progress.py`、`submission_audit.py` 能验证其覆盖的同源/版式/提交条件，但不能凭一个 PASS 报告证明整个数值依赖图已经重算。
