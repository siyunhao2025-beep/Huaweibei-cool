# modules/kickoff-audit.md · 开赛审计清单

> **目标**：题面一到手，在进入建模之前，先完成一次**反 AI 读题审计**——逐段拆解、列约束、列歧义、出建模候选与图表计划，经用户确认后才允许求解。对应 P0–P1。
>
> **先立假设**：华为杯出题组会**刻意"反 AI"命题**——诱导套路、隐藏约束、歧义陷阱。
> 默认题面处处是坑。**宁可慢、宁可多问、宁可把不确定性摆到台面上，也不许抢跑下结论。
> 千万不要聪明反被聪明误：凭模式匹配一眼看出"这题是 TSP/回归/分类"就直接套模板，正是出题组想钓的鱼。**

## 1. 反 AI 命题意识：陷阱清单（读题前先过一遍）

读题时逐条自问"这一处会不会是坑"。至少覆盖 7 类：

1. **诱导性标准套路**：题面措辞看似经典模型（TSP/回归/分类/排队论/整数规划），但**数据条件、假设、目标并不满足**——直接套模板必错。判型器（playbook_match）说像什么，只是候选，不等于题真能套那个模型。
2. **藏在背景叙述里的关键约束**：看似无关的背景段落，实际给出边界条件、量纲、物理意义、评价口径。**背景段也要逐句拆**，不能只读"问题一/二/三"。
3. **多小问的隐含依赖**：后问依赖前问结果；或某问要求**换方法/换数据/换口径**；小问之间有输入输出关系。跳读会漏，必须画依赖图。
4. **开放项陷阱**："自行收集数据 / 自定义指标 / 合理假设 / 自行选择"处是**评分分水岭**。这类地方必须**显式声明你选了什么、为什么**，并在论文里论证，不能默认带过。
5. **术语与量纲单位陷阱**：数据字典字段的真实含义、单位制、量纲参考系；**异常值/缺失到底是信号还是噪声**（丢掉真实信号 vs 把噪声当真）。
6. **冗余干扰信息与刻意模糊表述**：题面故意给的多余材料，或用模糊词（"合理""适当""较大"）制造歧义。**模糊点必须列入歧义清单向用户提问，禁止自行脑补一个解释**。
7. **评价标准暗示**：题目对"精度 / 效率 / 可解释性 / 泛化 / 成本"的真实侧重藏在措辞里（反复出现"实时"= 效率；"可解释"= 要讲清楚为什么；"成本最低"= 目标函数）。读出真实评价侧重，建模权重才不跑偏。

## 2. 强制逐句逐段拆解流程（不得跳步）

**禁止只读摘要/关键词就开干**。按题目原文顺序逐段处理，长段逐句：

1. 每段产出**四元组**：
   - ① **原文摘录**（带段落编号，如 §P2.3）；
   - ② **用自己的话复述**（不许照抄，照抄说明没懂）；
   - ③ **提取事实/数据/定义/约束/评价口径**，逐条编号 **C1、C2、C3…**；
   - ④ **存疑点与歧义**，逐条编号 **Q1、Q2…**。
2. 全部段落拆完做**交叉核对**：
   - 约束之间是否矛盾（C 与 C 冲突）；
   - 小问之间的**输入输出依赖图**（谁的结果喂给谁）；
   - 哪张数据表对应哪个任务。
3. 每个**建模设想必须回链题面证据**（约束编号 Cx）。**无证据的建模选择一律标"待论证"**，禁止凭"这题通常用 XX"直接定模型。
4. **playbook_match 的判型结果在此环节只许作为"候选假设"**（见 `problem-typing.md`），必须经题面证据逐条质证后才采信；置信度不足就**并列多个候选原型**，不锁死。

## 3. 读题审计报告（求解前必须产出的门禁文档）

报告至少含 7 节，写进工作目录（如 `题目/reading_audit.md`）：

1. **逐段拆解表**：四元组全文（§Px → 复述 → Cx → Qx）。
2. **任务大纲**：每小问的输入 / 输出 / 交付物 / 评价口径 / 小问依赖关系图。
3. **约束与假设清单**：已知约束（Cx）vs **待用户确认的假设**；开放项给**备选处理方案**（A/B/C）。
4. **陷阱与歧义清单**：每条歧义给"**若按 A 理解则…／若按 B 理解则…**"的影响分析（对建模、结果、工作量各有什么后果）。
5. **建模方案大纲**：每个任务给 **≥2 个候选模型/方法对比**——适用性、假设满足度、风险、工作量、创新空间；给推荐与理由，但标"**待用户确认**"。
6. **图表计划（逐张列出）**：图号 / 图类型 / 要表达的逻辑或结论 / 数据来源 / 对应小问 / 信息量设计 / 配色方案。要求：**复杂有逻辑、配色专业**（专业期刊审美 + 色盲友好 + 黑白打印可区分），鼓励机制示意图/流程图/结果复合图，**禁止低信息量裸图**；对接 `skills/academic-figure` 与 `scripts/visual_plan_init.py`（见 `figures-interface.md`）。**图号从"图1 技术路线图"起排**——它是默认首图（数据→预处理→各小问模型链→求解→验证→反馈回路），按 `technical-roadmap.md` 用 YAML 规格 + 渲染器生成，不手画。
7. **数据处理与复现性大纲 + 时间分配建议**。

## 4. 人工确认门禁（P1 硬退出条件，不可绕过）

- 报告**必须先完整呈现给用户审阅**，明确请用户判断：理解是否准确、有无漏题、模型与图表路线是否认可、歧义如何裁决。
- **必须等用户明确确认后才允许进入求解**；用户有异议就修订报告、重新提交，可多轮。
- 用户的**每一条裁决意见与确认结论写入 `evidence-ledger.md`（证据台账）**，作为后续所有建模决策依据。
- **无用户确认记录 = P1 门禁不通过**（见 `docs/PHASE_GATES.md`）。
- 比赛日再紧张，**只允许压缩报告篇幅，不允许取消"先呈现、等确认、再动手"**。
- 这是硬纪律：宁可慢、宁可多问、宁可把不确定性摆到台面上，也不许抢跑下结论。

## 5. 官方规则核对（最高优先级）

按当届官方通知逐条打勾。论文格式和 AI 使用以 docs/OFFICIAL_FORMAT_2026.md 记录的官方 Word 文件为基线；题目数量、选题方式和附件要求仍须以当届题面/系统为准：

- [ ] 选题方式、题目数量和题号：按当届题面与竞赛系统确认，不沿用历史 A–F 假设。
- [ ] 摘要页规则：论文题目、摘要、关键词写在摘要页，摘要页下一页才是正文。
- [ ] 页码：从摘要页开始，页脚中部阿拉伯数字，从 1 连续编号。
- [ ] **无页眉**；物理首页为第 0 页官方参赛信息封皮，除该页外不得出现任何显示答题人身份的标志。
- [ ] 字体：题目三号黑体、一级标题四号黑体居中、正文小四宋体、单倍行距。
- [ ] 摘要篇幅一般不超过两页，含建模思路/方法/模型/结果/结论/创新点/关键词，无需英译。
- [ ] 正文引用方括号编号 [1][3]；书籍引用要带页码；参考文献按引用次序。
- [ ] 是否需要上传代码/源程序（题面要求时）。
- [ ] **AI 使用核对**：按 2026 规定，如实确认是否使用；数据分析、编程、AI 来源模型/公式等按对应方式标注，未使用不得虚构披露（见 `submission.md`）。
- [ ] 正文页数上限：研赛格式规范未明确，**标"待确认"，查当届参赛通知**。

> 官方未给的细节，才用本仓库默认；官方一给，立即覆盖。

## 6. 题面硬约束提取（配合第 2 节逐段拆解落地）

把第 2 节抽出的 Cx 约束归到四列填表：

| 列 | 内容 |
|---|---|
| 直接目标 | 每一问要输出什么 |
| 已知条件 | 给了哪些数据/参数/图 |
| 硬约束 | 单位/量纲/取值范围/禁止项/必须的输出格式 |
| 隐含目标 | 没明说但必须做的（如评价要给排序） |

- [ ] 连续/离散变量已分清。
- [ ] 量纲与参考系统一（时间基准、坐标原点、单位制）。
- [ ] 题面"禁止/不建议机器学习"类字样已标出（见 `solving.md` 7.5/7.6 精神）。

## 7. 数据完整性检查

- [ ] 附件全部下载、解压（.rar 需 7-Zip/WinRAR，Expand-Archive 不支持）。
- [ ] 原始数据只读备份一份，不直接改原件。
- [ ] 每张数据表：行列数、缺失率、异常值、量纲、时间/空间对齐已记录。
- [ ] 多文件数据：主键/时间戳/空间坐标可对齐。
- [ ] 缺数据：列出"必须补/可选补"，不靠瞎编（见 `evidence-ledger.md`）。

## 8. 环境初始化验证

- [ ] `scripts/contest_init.py` 跑通，目录骨架就位。
- [ ] Python：`numpy/pandas/scipy/sklearn/matplotlib` 可 import。
- [ ] MATLAB：能起，`fmincon/intlinprog/ga/ode45` 等关键求解器可用（用户主力）。
- [ ] LaTeX：`assets/paper-template/gmcmthesis.cls` 可编译。
- [ ] 中文出图不方块（字体反乱码门禁，见 `figures-interface.md`）。

## 9. contest.json 填写

`config/contest.json` 必须填：届次、题号、队号占位、页数门禁值、AI 披露开关、corpus 路径占位。**届次/题号每年重置，严禁沿用上届**。

## 10. 边界与常见错误

- 不要把上一届的格式要求当本届；每届重查 cmathc.org.cn。
- 数据缺就标"待确认"，禁止用编造数字填论文。
- 原始语料/题面 PDF 只读，不删不改。
- **判型 ≠ 定模型**：playbook_match 只给候选，未过题面证据质证+用户确认前，不许开干。
- **跳过读题审计直接建模 = 抢跑**，是本模块最严重的错误；宁可把歧义摆给用户，也不要自己脑补。
