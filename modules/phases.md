# modules/phases.md · P0–P6 阶段契约详表

> **目标**：每个阶段"输入—必做动作—产物—门禁—卡点—时间预算"一屏看清；门禁是**内容级**（不是文件存在级），脚本化检查见 `docs/PHASE_GATES.md`。

## 通用字段

- **门禁**：内容级判定标准，未过不许进下一阶段。
- **卡点**：该阶段最常见的塌方点与处置。
- **时间预算**：占 72h 的比例，经验值。

---

## P0 环境初始化（预算 ~4%）

- **输入**：官方题面 PDF、官方规则/格式通知、AI 使用规定。
- **必做动作**：
  1. 运行 `scripts/contest_init.py` 生成工作目录骨架（题目/数据/求解/论文/提交附件）。
  2. 核对 `config/contest.json`：届次、题号、队号占位、页数门禁、AI 披露开关。
  3. 验证工具链：Python 可 import 核心库；MATLAB 可起；LaTeX/Word 模板可编译。
  4. 题面与规则落盘到 `题目/`。
- **产物**：目录骨架、填好的 `contest.json`、环境自检记录。
- **门禁**：题面+官方规则已落盘；`contest_init` 无报错；能跑 hello-world 求解脚本。
- **卡点**：压缩包（.rar）未解压、中文路径乱码、缺库。处置见 `kickoff-audit.md`。

## P1 读题与拆解（预算 ~12%）

- **输入**：题面、附件数据。
- **必做动作**：
  1. 逐问拆"直接目标/隐含目标/已知/约束"。
  2. 提取硬约束：单位、量纲、取值范围、禁止项、必须输出的结果格式。
  3. 数据审计：缺失/异常/量纲/规模（见 `solving.md` 读题节）。
  4. 选题决策（多题选一时）：跑 `scripts/playbook_match.py` 初判原型，对照 `tracks/` 档案。
  5. 题型判定：主原型 + 辅原型，记录匹配依据。
- **产物**：题面约束清单、选题结论、`match_rules` 命中记录、问题拆解表。
- **门禁**：题意无歧义（有歧义就停，不猜）；主原型已定；数据完整可读。
- **卡点**：把"赛道字母"当固定含义（**字母按届重置**，见 `track-selection.md`）。

## P2 建模（预算 ~22%）

- **输入**：约束清单、题型判定。
- **必做动作**：
  1. 列假设 ≥3 条，每条写"内容—合理性—影响"。
  2. 先基线（最简可用模型），再主模型，再改进；每步写"为什么换"。
  3. 定变量表（决策/中间/目标，类型/单位/范围）与目标函数。
  4. 从 `playbooks/<原型>/` 选方法卡，走 baseline→改进链。
- **产物**：假设清单、变量表、模型链、目标函数、基线结果。
- **门禁**：假设 ≥3 条；基线模型已跑通出数；无基线不进主模型。
- **卡点**：一上来就上复杂模型（LSTM/RL）而无基线；假设写"不影响结果"这种空话。

## P3 求解（预算 ~25%）

- **输入**：模型链。
- **必做动作**：
  1. 编码求解，固定随机种子，结构化落盘（.mat/.csv/.json）。
  2. 每问出结果图（走 visual plan）。
  3. 同步做验证：误差/对比/灵敏度/鲁棒性/消融（见 `validation.md`）。
  4. 关键结论进证据账本（见 `evidence-ledger.md`）。
- **产物**：求解脚本、结果文件、图、验证记录、账本条目。
- **门禁**：结果可复现（重跑一致）；≥1 种验证手段有结果；关键数字进账本。
- **卡点**：只报结果不给对比；数字散在控制台没落盘；换 seed 结果漂移。

## P4 论文初稿（预算 ~20%）

- **输入**：各问结果与验证。
- **必做动作**：按章节成稿（见 `paper-writing.md`）：摘要/问题重述/假设/符号/各问建立求解/检验/灵敏度/结论/参考文献/附录；**写作时逐章节对照 `assets/checklists/优秀论文自检表.md` 边写边勾**（每完成一章立即勾选对应条目，不堆到最后）。
- **产物**：初稿（LaTeX 或 Word）、边写边勾的自检表。
- **门禁**：章节齐全；摘要篇幅一般不超过两页；正文页数在基线窗口（`page_targets.json`，历史经验 45 页级，**以当届官方为准**）；图表在正文被引用；比赛工作目录下存在自检表文件（`论文/优秀论文自检表.md`）。
- **卡点**：最后一夜才写初稿；摘要写"效果良好"无数字。

## P5 打磨审校（预算 ~12%）

- **输入**：初稿。
- **必做动作**：去 AI 味（`deai-writing.md`）、格式审校、引用审校、数字一致性、封皮后匿名化（见 `polishing.md`）。
- **产物**：终稿。
- **门禁**：`scripts/audit_tex.py`/`audit_docx.py` PASS；无页眉且封皮后无身份标志；摘要-正文-附录数字一致；无残留 TODO。
- **卡点**：学校名/姓名漏在页眉或图里；AI 生成段落未改写。

## P6 提交与蒸馏（预算 ~5%）

- **输入**：终稿 + 代码/数据附件。
- **必做动作**：提交审计（`submission_audit.py`）、AI 披露按 2026 规定写、打包上传、赛后蒸馏（`distillation.md`）；**终审运行 `scripts/paper_checklist.py --strict`，对自检表 100% 闭环**（机检 0 ❌ + 人工条目 `--mark` 全裁决 + 产出《论文自检表_已勾选.md》）。
- **产物**：提交包、AI 使用说明、赛后方法卡、已勾选自检表。
- **门禁**：提交审计 PASS；AI 使用已按实际方式完成对应标注或明确未使用；附件清单完整；**自检表 100% 闭环**（机检 0 ❌、sidecar 无未裁决人工条目、已勾选自检表落盘）。
- **卡点**：漏交代码附件；AI 披露漏"程序开头注释"；自检表留未裁决项/未解释 ❌ 就提交。

---

## 回退规则

- P3 结果不可复现 → 回 P3 修代码，不带病进 P4。
- P5 数字不一致 → 回 P3 重核对，不手工凑数。
- 任何阶段发现题意理解错 → 回 P1，不硬写。
