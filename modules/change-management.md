# modules/change-management.md · 变更管理

> **目标**：比赛中改模型/方法/数据时，知道会连锁影响什么，别改一处崩三处。72 小时里必改，关键是改得可控。

## 1. 为什么要管变更

比赛中"换模型""改假设""换数据"是家常便饭。不改记录的后果：摘要还是旧数字、验证没重跑、附录代码与正文不符。

## 2. 版本控制

- **建议用 git**（仓库已 init）：每完成一个可跑的节点就 commit，写清"改了什么/为什么"。
- 没有 git 时：用版本目录 `v1_baseline/ v2_main/ v3_improved/`，不直接覆盖上一版结果。
- 原始数据永远只读，另存处理后副本。

## 3. 变更影响评估（改之前先想）

每改一处，问四个连锁：

| 改了什么 | 连锁影响 |
|---|---|
| 换模型 | 结果数字变 → 摘要/正文/附录全要更新；验证要重跑；创新点表述可能变 |
| 改假设 | 模型推导要重推；灵敏度分析可能要重做 |
| 换数据/预处理 | 所有结果重跑；对比基线要在同数据上重算 |
| 改目标函数 | 优化结果全变；图表重出 |

## 4. 记录规范

每次变更记一行：

- 时间 / 改了什么 / 为什么改 / 影响了哪些章节 / 哪些验证要重跑。
- 策略选择另记：小问 / A、B 证据路径 / 推荐及理由 / 用户选择 / 回退版本。用户未选择前不覆盖当前主路线。

## 5. 回退预案

- 改崩了能一键回到上一个可跑版本（git 或版本目录）。
- D3 之后**冻结主版本**：只改文字和格式，不再动模型和结果，避免临交前数字又变。
- 重大改动（换主模型）只允许在 D2 中午前；之后只做小修。

## 6. 常见错误

- 改了模型忘了改摘要。
- 重跑结果后没更新附录。
- 没有版本备份，改崩了找不回上一版。
- D3 深夜还在换模型，结果来不及验证就交。
