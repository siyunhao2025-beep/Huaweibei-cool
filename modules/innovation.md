# modules/innovation.md · 创新点提炼

> **目标**：把你做的事提炼成评委认的"创新点"，而不是"我用了 XX 算法"。从 S3 数模之星 12 篇（`S3_star_patterns.md` 模式 5–9、16–17）和 80 深卡的 `innovation_points`/`judge_high_score_reasons` 提炼。

## 1. 国一创新点五种模式

| 模式 | 是什么 | 语料范例（paper_id） |
|---|---|---|
| 结构洞察型 | 先看清数据/机理长什么样再选算法 | A21102860073 先分析相关性/稀疏性再选算子；A21102910019 发现右奇异向量↔H*H 特征向量 |
| 分而治之型 | 对不同子对象用不同模型，不一刀切 | B21105610069 常规污染物 FNN / O3 降噪 SVR / 时序 LSTM / 空间 GCN |
| 链式升级型 | 上一模型哪里不好→针对性改进 | B21105610069 FNN 偏差 17.14→CEEMDAN→LSTM；E21104870136 LS 依赖初值→改 MLP |
| 跨域迁移型 | 把别的领域模型迁过来 | B21106990088 生态学 Lotka-Volterra 修 O3/NO2 耦合；D21102800176 原型网络小样本 |
| 双轨互验型 | 精确解/启发式双轨互验 | F21102480018 ILP 精确解+启发式互验；A24102940057 自研 RRF 对标 MATLAB rainflow |

> 2024 高分新范式：**物理机理打底 + ML 学残差 + 消融/对标**（A/C/F 三赛道物理回归）。

## 2. 创新点表述模板（三件套）

星队创新点不是"我用了 XX"，而是：

> **观察到 X 现象 → 把 Y 换成 Z → 收益 N%**

范例：
- 观察分块间强相关 → 上一块解作下一块初值 → 迭代仅 2~3 次（A21102910019）。
- LS 依赖初值 → 重述为可微优化用 MLP → 不依赖初值抗噪（E21104870136）。
- 0-1 相乘非线性 → 辅助变量线性化 → 可解且 ε=45 最优（F21102480018）。
- 把工程/物理约束写进目标函数，体现落地意识（电池使用写进 DBS 损失、环形风向物理编码）。

## 3. 评委给高分的具体信号（从 judge_high_score_reasons 提炼）

- 先做数据/机理分析再选算子，不是套算法。
- 建立复杂度/成本表，把步骤折算成可比量，严谨可复算。
- 多个改进层层叠加，每层给量化降幅。
- 给两条路线并说明各自适用场景，体现权衡。
- 算法原创解决两个痛点，并有外部对标验证。
- 工程化思路完整（如 RL 无法硬约束→给安全层校正的工程解法）。

## 4. 伪创新识别清单（别写）

- [ ] "使用了 XX 算法"本身不是创新点（算法是工具）。
- [ ] 把三个经典算法拼起来没说清为什么拼、解决了什么痛点。
- [ ] 创新点无量化收益（"提高了精度"是废话）。
- [ ] 跨域迁移却说不清迁的是什么、为什么适合本题。
- [ ] "首次提出"但查不到任何依据（评委见过的太多）。
- [ ] 创新点和正文做法对不上（说用了 A，正文全是 B）。

## 5. 操作

- 每问做完后，按"三件套"写 1–2 句创新点草稿。
- 从 5 种模式里找你的创新落在哪类，挂上语料范例做对照。
- 摘要里的创新点与正文一致。

## 6. 边界

- 创新点从真实做法来，不硬编"首次/首创"。
- 小改进也是创新（降复杂度、改预处理），不必非得重大理论突破。
- 不夸大；评委对包装很敏感。
