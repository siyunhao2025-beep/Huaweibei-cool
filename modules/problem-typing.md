# modules/problem-typing.md · 题型判定（题面→候选原型）

> **目标**：拿到题面，用 `playbooks/match_rules.json` 把它**初步匹配**到 8 大原型之一，作为**候选原型假设**交给读题审计环节质证，再决定主/辅原型。对应 P1。
>
> **硬声明（反 AI 抢跑）**：本模块的判型结果**只是候选假设，不得直接采信、更不得据此直接定模型**。
> 出题组会"反 AI"命题——题面看似某经典模型，条件却不满足。判型必须经
> `kickoff-audit.md` 第 2 节"逐段拆解 + 题面证据逐条质证"后才采信；
> 置信度不足时**并列多个候选原型**。**禁止"判型 = 定模型"的跳步。**

## 1. 8 大原型触发特征速查

| 原型 | 触发核心信号 | 方法卡目录 |
|---|---|---|
| optimization | 约束下求极值：排样/调度/分配/选址/路径/成本最低 | `playbooks/optimization/` |
| evaluation | 多指标打分/排序/优选/指标体系 | `playbooks/evaluation/` |
| prediction | 外推未来/未知量：预测/预报/趋势/时序 | `playbooks/prediction/` |
| classification-cv | 分类/识别/聚类/分割/检测/故障诊断 | `playbooks/classification-cv/` |
| mechanism | 第一性原理方程：微分方程/动力学/机理/传染病/分岔 | `playbooks/mechanism/` |
| signal | 采样信号：谱估计/滤波/雷达回波/DOA/阵列/振动 | `playbooks/signal/` |
| spatial-graph | 空间/图/网络/路径/GIS/布局/空间插值 | `playbooks/spatial-graph/` |
| simulation | 随机仿真/排队/蒙特卡洛/多智能体/随机过程 | `playbooks/simulation/` |

## 2. 匹配流程

1. 把题面全文（含附件说明）存成 txt。
2. 跑 `python scripts/playbook_match.py --txt <题面.txt>`（或 `--stdin`）。
3. 看输出：top 原型、置信度、命中关键词、推荐方法卡——**这只是候选假设**。
4. **质证后才采信**：把候选原型带回读题审计（`kickoff-audit.md` §2），逐条对题面约束 Cx 检查"该模型的假设/条件是否真的满足"。脚本说"建议"，不是"判决"。
5. **置信度不足并列多候选**：top 置信 < 0.8、或多个原型打平时，把 2–3 个候选连同适用性一起列进读题审计报告 §5，交用户裁决，不锁死。
6. 质证通过后：定**主原型**（决定主模型链）+ **辅原型**（决定验证/对比或混合模块）。

## 3. 置信度与判定

- 规则 `confidence ≥ 0.8`：可直接采纳为主原型。
- `0.6–0.8`：作为强候选，人工看命中关键词是否切题。
- 多个原型同分：按 `match_rules.json` 的 tie_break（confidence 高者先，同分 rule_id 小者先）。
- 最高 < 0.5：标 `unknown`，人工读题判断，不要硬套。

## 4. 跨原型题的处理

一篇论文常跨多原型（语料事实：同一篇可命中多列）。处理：

- **主原型**：题目核心任务（求极值？打分？外推？识别？）。
- **辅原型**：支撑模块。常见组合：
  - optimization + evaluation（先优化再评价方案优劣）。
  - prediction + mechanism（物理方程打底 + ML 学残差，2024 高分范式）。
  - classification-cv + evaluation（分类后对类别评价）。
  - signal + optimization（信号处理后做资源分配）。
- 跨原型时，主方法卡从主原型目录选，辅模块从辅原型目录借（见各卡"相邻方法辨析"）。

## 5. 示例（语料真实命中）

- "风电场有功功率优化分配 + 疲劳损伤" → 主 optimization，辅 mechanism（雨流计数/疲劳物理）。
- "出血性脑卒中临床诊疗" → 主 prediction（预后预测），辅 classification-cv（亚型聚类）。
- "强对流降水临近预报" → 主 prediction（时空预测），辅 signal（双偏振雷达）。

## 6. 边界

- 关键词规则是粗筛工具，**不替代读题**；脚本输出仅供建议。
- **判型是候选、不是定案**：未经读题审计质证与用户确认，不许把候选原型写成最终模型。
- 方法名触发规则（R09–R13）置信度低，只是提示"可能是这类"，别当主依据。
- 题型判错不致命，但会选错方法卡，浪费半天；判完再花 10 分钟复核题面关键词。
- 出题组可能用"看似 TSP/回归/分类"的措辞诱导套模板——凡模型假设对不上题面约束 Cx，一律弃用该候选。
