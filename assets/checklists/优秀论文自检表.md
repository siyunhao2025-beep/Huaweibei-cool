# 华为杯研赛论文自检表（人读版）

> 用法：写作时逐章核对，终审时全量闭环；机检脚本为 `scripts/paper_checklist.py`。
> 共 138 个检查 ID。F01–F06 来自官方格式基线；其余是第三方清单、获奖论文经验与第二十三届社区 LaTeX 参考包的融合结果，不是官方硬性评分细则。
> “闭环”是每项均有“通过/不适用及理由/未做到及风险”结论，不等于强行让 138 项全部通过。题面、数据结构和证据优先于固定段数、页数、算法名与图表数量。

## 〇、全局格式（硬性）

- [ ] F01 论文题目用三号黑体字
- [ ] F02 一级标题用四号黑体字，居中
- [ ] F03 二级、三级标题用小四号宋体字，左端对齐（不居中）【以官方格式规范为准，第三方原写“黑体”不采纳】
- [ ] F04 论文中其他汉字一律用小四号宋体字；排版文本中的英文、阿拉伯数字和西文标点用 Times New Roman（Overleaf 缺少该字体时用 TeX Gyre Termes 兼容回退；公式与代码分别保留数学字体和等宽字体）
- [ ] F05 行距用单倍行距
- [ ] F06 打印文字尽量避免不必要的彩色；必要彩图须保证灰度打印仍可辨

## 一、章节结构与篇幅（经验项，按题目自适应）

- [ ] L01 流程图仅在能提升理解时使用，缩放后文字、箭头和层级清楚
- [ ] L02 模型假设只保留真正影响模型的条目，篇幅从简
- [ ] L03 符号说明覆盖核心符号、含义与必要单位，表格紧凑可读
- [ ] L04 问题分析足以说明输入、输出、目标、约束、成功标准和问题依赖
- [ ] L05 数据与模型准备篇幅与实际数据审计、预处理和选型工作量相称
- [ ] L06 模型建立完整呈现变量、假设、目标/方程、约束和参数来源，不按固定页数凑篇幅
- [ ] L07 模型求解写清算法/求解器、关键参数、停止条件及必要的复杂度或收敛信息
- [ ] L08 模型检验按题型、数据结构和结论风险选择，不机械单列或凑篇幅
- [ ] L09 每个问题都形成“任务—模型—求解—结果—验证—结论”的闭合证据链
- [ ] L10 统一检验章只容纳跨问题的共享验证，避免重复各问已有内容
- [ ] L11 模型优势只写有结果、对比或理论依据支持的部分
- [ ] L12 模型局限按真实风险完整披露，不为版面或数量对称而删减
- [ ] L13 已验证的改进与尚未实现的未来改进分开陈述
- [ ] L14 推广说明新场景差异、重标定需求与重新验证条件
- [ ] L15 参考文献数量由实际引用决定，确保正文引用闭合、格式合规
- [ ] L16 附件说明按题面和竞赛系统要求提供，不为凑页新增材料
- [ ] L17 附录代码/结果按需要提供，并包含最小复现元数据

## 二、摘要（一般不超过两页）

**任务与背景**
- [ ] A01 用最短篇幅点明核心任务或矛盾，不强制两句话或固定段数

**逐问信息闭环**
- [ ] A02 每一问均可清楚识别，不强制使用“针对问题#”固定句式
- [ ] A03 说明该问的任务类型或核心目标，避免只报算法名
- [ ] A04 点出主要模型/方法及其作用
- [ ] A05 按真实逻辑连接关键步骤，不机械堆“首先、接着、最后”
- [ ] A06 展示可追溯的关键结果、单位和评价口径；主要模型、决定性数值及核心结论/创新点适度加粗，普通数字不机械加粗且不整句加粗
- [ ] A07 不展开检验过程，但核心结论需要时保留一项关键验证证据或风险边界
- [ ] A08 删除空泛解释，保留理解结果所必需的因果、意义、代价和适用边界

**收束**
- [ ] A09 用 1–2 句概括有证据的贡献、适用边界或决策价值；无比较证据不得称“性能优越”

**关键词**
- [ ] A10 关键词通常 3–6 个，覆盖问题领域与核心方法，不重复堆同义词

## 三、引言 / 问题重述（按题目需要）

**必要背景**
- [ ] B01 只保留理解题目所需背景，不强制纯背景开头或固定句数
- [ ] B02 说明问题来源、应用语境或数据语境，来源可核查
- [ ] B03 明确现有困难、信息缺口或决策冲突
- [ ] B04 说明本文需要完成的具体任务，不写空泛“迫切需求”
- [ ] B05 段落数量服从逻辑，不机械限制为 2–3 段
- [ ] B06 以自然段为主；确需列任务或约束时可使用清晰列表

**研究/应用意义（可选）**
- [ ] B07 仅在有助于理解任务时写社会、工程或科研意义
- [ ] B08 每项意义能与题目目标或实际决策对应，不凑数量
- [ ] B09 意义表述可用自然段或短列表，以清晰为准
- [ ] B10 删除宣传式、不可验证或与赛题无关的价值判断

**问题重述**
- [ ] B11 每问准确提炼输入、输出、目标和约束，长度按复杂度决定
- [ ] B12 问题编号或标签清楚一致；是否加粗服从版式与可读性
- [ ] B13 问题标签后的标点和句式统一
- [ ] B14 多项任务可使用列表，避免因禁止分点而写成长句
- [ ] B15 用自己的话提炼题意，不复制背景和附属说明，也不改变原意

## 四、总体分析（可选）

- [ ] T01 结构服从整体逻辑，不强制三段式
- [ ] T02 简要说明总体主线和建模边界
- [ ] T03 明确各问的依赖、共享数据/参数及误差传递关系
- [ ] T04 为各问说明方法选择理由，不使用固定占位句
- [ ] T05 只有正文需要引用流程图时才写图引文，并说明图表达的主线
- [ ] T06 流程图由真实任务、数据、模型、求解和验证关系生成，不套固定框图
- [ ] T07 图中节点、箭头、正文叙述和实际代码/模型一致
- [ ] T08 可说明计划采用的验证逻辑，但不得提前虚构检验结果或求解数字

## 五、模型假设

- [ ] H01 假设按逻辑组织，不强制两段式
- [ ] H02 说明每条假设为何必要、依据何在
- [ ] H03 每条假设表述清楚，并指出可能影响的变量或结论
- [ ] H04 假设编号与正文引用一致，不强制使用“假设#：”字面格式
- [ ] H05 假设数量由模型需要决定，不与问题数量机械相等
- [ ] H06 重要假设在灵敏度、鲁棒性或局限部分得到检验或讨论

## 六、符号说明

- [ ] S01 用一句话引出符号表或变量字典，避免重复正文
- [ ] S02 只收录核心或易混符号，普通临时量可在首次出现处解释
- [ ] S03 使用三线表；按需要选择“符号/含义”或增加“单位/取值域”等列
- [ ] S04 表题和唯一标签完整，正文有引用时引用闭合
- [ ] S05 每行字段尽量短；确需换行时保证对齐与可读性
- [ ] S06 列名样式与全文表格一致，不以是否加粗作为质量标准

## 七、具体分析（各问题内）

- [ ] C01 明确正在回答的题目小问
- [ ] C02 说明任务性质、评价标准或主要难点
- [ ] C03 给出所选方法及选择依据，而非只列算法名称
- [ ] C04 按真实依赖关系描述步骤，不强制固定连接词
- [ ] C05 结构可用自然段、短列表或小图，以读者能复现思路为准
- [ ] C06 包含输入、输出、目标、约束和成功标准的最小任务卡信息
- [ ] C07 说明本问与前后问题的数据/参数/误差传递；无依赖时明确说明
- [ ] C08 仅当流程复杂且图能增益理解时使用流程图

## 八、模型准备

**数据审计与预处理**
- [ ] P01 交代数据来源、规模、字段、单位、时间/空间粒度和使用去向
- [ ] P02 说明缺失、异常、重复、噪声或量纲问题及判据
- [ ] P03 写明实际执行的预处理步骤、顺序和参数来源
- [ ] P04 给出必要公式，并说明归一化参数如何估计与反变换
- [ ] P05 仅在能证明处理效果时给前后对比图/表；否则用可核查统计量
- [ ] P06 编码、特征或中间数据可追溯到脚本和结果文件

**方法选择**
- [ ] P07 先建立朴素规则、经典方法、理论边界或精确小规模解作为 Baseline
- [ ] P08 只比较适用于本题且能公平实现的候选方法
- [ ] P09 候选比较使用同一数据、划分、指标和计算预算；图表形式按证据选择
- [ ] P10 同时报效果、稳定性、约束满足、计算成本和解释代价，给出选择理由
- [ ] P11 明确最终方法及不选择其他候选的原因，随后进入模型建立/求解

## 九、模型建立

> 组合题型按主要任务选择适用项，不要求全部通过；不适用项必须记录理由。

**优化类**
- [ ] M01 决策变量、目标函数及方向定义完整
- [ ] M02 硬约束、软约束、变量域与可行性处理完整
- [ ] M03 说明求解算法为何适用，并给必要的精确解/下界/小规模互验方案

**机理分析类**
- [ ] M04 核心变量关系、方程、初/边界条件和参数来源完整，步骤数量按实际决定

**通用收尾**
- [ ] M05 用一句或一段总结模型输入、输出和待求量，自然引出求解

**评价类**
- [ ] M06 指标体系与题目目标对应，处理同向化、量纲和冗余相关性
- [ ] M07 权重方法依据数据与决策语义选择，不默认熵权法；展示权重及其稳定性
- [ ] M08 综合评价方法与数据性质匹配，并说明排序/分级规则

**分类类**
- [ ] M09 特征工程只使用训练阶段可获得的信息，并展示关键中间结果
- [ ] M10 分类模型由任务、样本量、非线性和解释需求选择，不预设逻辑回归/XGBoost
- [ ] M11 说明数据划分、类别不平衡处理、阈值和评价指标

**预测类**
- [ ] M12 特征工程避免未来信息泄漏，并展示关键中间结果
- [ ] M13 预测模型由时间/空间结构、样本量和外推需求选择，不预设 XGBoost
- [ ] M14 说明验证划分、损失/指标、超参数选择和输出约束

## 十、模型求解与结果

- [ ] Q01 先直接回答本问，再引出支撑答案的结果表/图
- [ ] Q02 图表尺寸按内容和版心调整，缩放后文字清晰、无溢出；不固定为 0.8 倍正文宽
- [ ] Q03 图题、轴名和图例以中文为主；公认缩写、变量和单位可保留英文/符号
- [ ] Q04 每张图表有唯一题注和标签，并在正文按出现顺序引用
- [ ] Q05 按“答案—证据—比较—解释—边界/代价”组织结果，不强制三段式
- [ ] Q06 精确数字适合用表时用表；少量关键数字可直接写入正文
- [ ] Q07 趋势、分布、关系或方案差异适合用图时才用图
- [ ] Q08 删除装饰性、无法支撑结论或无法追溯数据的图
- [ ] Q09 分点和加粗只在确能提升结构与可读性时使用，并保持克制一致

## 十一、模型检验（按题型与风险选择）

**检验内容**
- [ ] V01 评价类检验权重敏感性、排序稳定性和必要的一致性/外部对照
- [ ] V02 分类类按任务报告混淆矩阵、精确率、召回率、F1；准确率/AUC 仅在适用时使用
- [ ] V03 预测类报告合适的误差、残差与外推/滚动表现
- [ ] V04 优化类检查约束可行性、收敛、最优性边界和关键参数敏感性
- [ ] V05 划分服从数据结构：IID 用 k 折，分组用组间留出，时序用滚动/扩展窗口，空间用分块
- [ ] V06 灵敏度分析明确扰动对象、范围、依据和输出稳定性指标

**写作方式**
- [ ] V07 检验结论由真实结果文件支持；AI 可辅助表述，但作者须核验并按当届规定披露

## 十二、模型检验与分析（可就地或统一书写）

- [ ] W01 说明每项检验要排除的风险或要支持的结论
- [ ] W02 多种检验用清晰小标题区分，单一检验不为形式强拆标题
- [ ] W03 解释检验设计、数据隔离和适用前提
- [ ] W04 按信息类型选图、表或统计量，不机械“表优先”
- [ ] W05 解释结果、失败情形、置信范围和对正文结论的影响

## 十三、模型评价

**优势**
- [ ] E01 优势标题格式简洁一致，不强制“优点#：”字面样式
- [ ] E02 按模型机制或证据写优势，必要时指出对应问题
- [ ] E03 优势数量由证据决定，不要求机械多于局限
- [ ] E04 每项优势指向前文精度、稳定性、效率或解释性证据

**局限**
- [ ] E05 局限标题格式简洁一致，不强制“缺点#：”字面样式
- [ ] E06 每项按“来源—偏差方向—影响范围—缓解办法”书写
- [ ] E07 重大局限不得因数量配额被隐藏
- [ ] E08 表述简洁但信息完整，必要时可超过两行

## 十四、模型改进

- [ ] I01 已实现且有同口径实验支持的改进才写成结果，AI 辅助文字须经作者核验与披露

## 十五、模型推广

## 十六、参考文献

- [ ] R01 以当届官方引用格式为准，按正文首次引用顺序编号；通用 GB/T 规则仅作补充
- [ ] R02 文献真实可核查且字段完整；DOI 不是官方强制删除项，也不得伪造或写入未引用来源

## 十七、附录

- [ ] X01 附件说明表仅在题面或提交系统要求时提供，并与实际上传文件一致
- [ ] X02 代码/结果按需要附；至少记录环境版本、入口命令、输入输出、随机种子和关键参数

## 执行要求

1. 每完成一章立即核对对应检查 ID，终稿再做一次全量复查；
2. 最终输出已闭环的检查表：通过打 ✅，不适用打 ➖ 并写理由，未做到打 ❌ 并说明风险；
3. 不得为了“全绿”强行添加不适用的章节、算法、图表、检验或结论；
4. 官方规则、题面和真实证据优先；发现冲突时记录裁决依据并同步 JSON 与审计脚本。
