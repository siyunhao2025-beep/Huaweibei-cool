# 用户提供的第 23 届 LaTeX 参考包：内容映射与取舍

## 1. 定位与优先级

本记录对应本机 skill 的 `assets/paper-template/reference-23rd-latex/`。原 PDF、正文源文件、类文件、样式和图像已在本机按 SHA-256 装载，完整清单见 `source-manifest.json`。源包未附明确再分发许可，因此公开 GitHub 只保存清单、映射和融合后的原创规则，不复制第三方原件。

该包的 `gmcmthesis.cls` 文件头写明由 `latexstudio.net` 创建并由社区作者更新，因此它是**用户提供的社区 LaTeX 参考包**，不是组委会发布的官方 LaTeX 模板。版式裁决始终以 `docs/OFFICIAL_FORMAT_2026.md` 所列官方公告、上传手册和 Word 附件为准；本包只提供正文组织与写作启发。

生产稿不得直接依赖本目录中的 `main.tex` 或 `gmcmthesis.cls`。生成论文时继续使用 `assets/paper-template/` 已核对的生产类文件、官方徽标资源和章节模板。

本次“完整融合”采用**逐页、逐节有结论**的含义：每一部分都标明吸收、改写、已有覆盖或拒绝及理由；不采用逐字复制。逐字复制会把目录、示例数字、通用占位公式和过期届次一起带入正式论文，反而破坏官方格式与证据真实性。

### 3.1 “主要符号说明”生产增补

参考包 §3.2 提供了变量字典与三线符号表的内容启发，但“每份正式论文都必须有一张主要符号说明表”是用户在融合后确认的内部生产规则，不是参考包的官方性证明，也不是已核对官方文件中的明文要求。生产稿将该表固定在基本假设/总体问题分析之后、第一问推导与全文首个模型公式之前；仅收全局核心符号，局部参数在首次出现处定义。表前必须有 `\ref`，表内必须有 `\caption`、唯一 `\label`、适用的单位/取值域和 booktabs 三线，禁止竖线、网格线、整体缩放及小字号挤压。

## 4. 小标题逐项写作映射

下面不是要求所有论文照抄同一目录，而是把参考 PDF 中每个小标题真正承担的内容显式写清。题目不适用时删除该标题，不保留空壳。

| 参考标题 | 标题下必须回答什么 | 建议证据/产物 | 不应写什么 |
|---|---|---|---|
| 1.1 从题面提取建模信息 | 各问输入、已知条件、硬约束、目标输出、问间依赖和歧义裁决 | 任务映射表、约束编号 | 逐句复述题面 |
| 1.2 评价标准与成功条件 | 什么指标/约束构成“答对”，阈值、单位和比较口径是什么 | 指标定义、成功判据 | 建模后才临时挑指标 |
| 2.1 统一建模思路 | 事实如何进入模型、结果如何验证、各问如何组成证据链 | **论文级总流程图 F01**、图前/图后解释 | 只有几只空框的通用流程图 |
| 2.2 模型复杂度控制 | 基线为何足够或为何需要加复杂度；新增模块带来什么实测增益与代价 | 基线—候选同口径对比 | 堆算法名、把未运行方案称优化 |
| 3.1 数据审计 | 样本量、字段、缺失、异常、重复、时间/空间范围、单位、来源、主键和泄漏风险 | 审计表、分布/质量图 | 只写“完成清洗” |
| 3.2 变量字典与方向统一 | 符号、含义、单位、范围、正负方向、变换与理由 | 三线符号表、定义公式 | 无解释地归一化/正向化 |
| 4.1 目标与建模策略 | 本问要识别/预测/评价/优化什么，为什么选择这条路线 | 任务卡、机理或结构证据 | 先报模型名再找理由 |
| 4.2 基线模型与改进模型 | 基线、主模型的假设/方程/约束/参数，以及公平比较 | 公式、算法、消融/对比表图 | 不同数据口径的“提升” |
| 4.3 结果传递 | 本问输出是否进入后问；传递量、单位、文件、误差和边界 | 接口表/结果索引 | 强造问间依赖 |
| 5.1 训练与验证划分 | IID/事件/时间/空间划分为何匹配数据结构，如何防泄漏 | 拆分图、样本计数 | 帧级随机拆分导致同源泄漏 |
| 5.2 模型训练与超参数选择 | 训练对象、搜索空间、选择指标、停止条件、随机种子和测试冻结 | 参数表、验证曲线 | 在测试集反复调参 |
| 5.3 评价指标与误差解释 | 指标定义、量纲、方向、冲突和误差来源 | 多指标表图、残差证据 | 用单一总分遮蔽代价 |
| 6.1--6.4 约束优化与方案设计 | 决策变量、目标、约束来源、求解方法、可行性、方案差异和约束余量 | 数学模型、求解日志、方案表 | 只给最优值不验可行性 |
| 7.1 拟合与残差诊断 | 误差如何分布，是否有偏、异方差、结构残差或失败场景 | 残差图/误差表 | 只报训练集拟合优度 |
| 7.2 交叉/滚动/独立验证 | 采用哪种独立验证、为什么、结果是否稳定 | 独立验证或滚动结果 | 对所有题机械五折 |
| 7.3 稳定性与敏感性 | 哪些参数/数据扰动会改变结论，触发换方案的阈值是什么 | 灵敏度曲线、稳健性区间 | 只说“结果稳定” |
| 8.1--8.3 不确定性与情景 | 观测、参数、情景不确定性分别来自哪里，区间/情景怎样改变结论 | Bootstrap/蒙特卡洛/情景矩阵 | 无依据假设分布 |
| 9.1 图表选择 | 每张图/表回答哪个独立问题，图与表如何分工 | visual plan、Figure/Table 账本 | 一份数据换多图型凑数 |
| 9.2 结果表述 | 图前如何定位、图注如何解码、图后读出什么证据、为何出现、对模型/答案意味着什么及其边界 | 图文六项详解合同 | 只写“如图所示”或只复述结果 |
| 10.1--10.3 评价、局限与推广 | 优点证据、局限来源/偏差方向/影响范围、可复用结构和需重估参数 | 验证结果、边界清单 | “先进、通用、精度高”等空话 |
| 11 结论 | 逐问直接给答案、关键量和适用范围，不引入新结果 | 答案清单、核心数字表 | 重复推导或新增实验 |

## 5. 融合后的正文契约

1. 每个编号问题先写“回溯—路线—交付”导读：说明本问目标、输入及真实问间接口，概括实际方法顺序和结果去向；再展开任务卡、模型、结果与验证，不以空泛“本节将”代替。
2. 数据驱动问题先完成数据审计和变量字典；没有数据附件时删除该小节。
3. 基本假设/总体问题分析之后、第一问推导与首个公式之前放一张“主要符号说明”三线表；只收全局核心符号，具备正文引用、题注、标签及适用单位/取值域，不用网格或缩放挤压。这是用户内部规则，不标作官方原文。
4. 模型链按“最简基线 → 主模型 → 有证据的改进”展开，不堆砌算法。
5. 结果段按“回答哪一问 → 数字/图表 → 与基线同口径比较 → 原因解释 → 适用边界或代价”展开。
6. 验证按题型与风险选择。评价问题也要做权重/排序稳定性；时间、分组和空间数据不得随机泄漏；组合模型只有在声称模块贡献时才要求消融。
7. 本问输出只有在确实被后问使用时才声明传递关系，不为叙事完整强造依赖。
8. 每个二、三级标题下先在源稿注释中填写“本节问题—输入/证据—方法/定义—结果—解释/边界—接口”内容卡；终稿不得出现标题空壳。
9. 每张 Figure 形成“图前定位—图注解码—证据读数—原因/机制—论文含义—边界/转折”；复杂多问论文的 §2.1 总图使用论文专属完整框架图，并通过入稿六联门禁。
10. 参考文献与附录分别另起一页；使用 `\clearpage` 清空浮动体，不以分页制造空白或凑篇幅。
11. 计算型论文的附录必须含本题专属代码式伪代码，覆盖输入审计、冻结配置、数据/求解边界、真实算法、独立检验与导出，并给出脚本/函数和结果文件映射；完整代码留在复现包。
12. 终稿不得保留参考包中的写作提示、占位符、目录、示例数字、通用公式或“第二十二届”资源。

## 6. 验收要求

- 本机存在源包时，六个文件的哈希与 `source-manifest.json` 一致；CI/公开克隆不要求持有第三方原件。
- 生产模板不引用 `reference-23rd-latex/`，不生成目录，不调用旧 `title.pdf`。
- 章节模板覆盖任务定义、数据审计、模型链、结果证据、验证/不确定性、结果传递、评价、结论和复现信息。
- `章节模板/符号说明模板.tex` 已提供可复制的 booktabs 骨架；正式稿的主要符号表位于首个模型公式之前，且正文引用、题注、标签、三线结构和符号一致性均闭环。
- 复杂多问论文的 F01 是从真实证据生成的完整框架图，而非通用空框；正式源图已绑定 LaTeX、正文引用、图注、图后解释和最终 PDF 页码。
- 每个二、三级标题有实质内容；每张图有图前定位和图后详解，详解包含证据、原因/机制、论文含义与边界，不依赖图注独自承担论证，也不把相关性偷换为因果。
- 计算型论文的附录存在可读的代码式伪代码，且每一步可追溯到实际运行脚本/函数和结果文件；没有空函数、占位符、未运行模块、绝对路径或身份信息。
- 编译、源码审计、逐页视觉检查和干净包复编译全部通过后，才可标记为 `tested`。
